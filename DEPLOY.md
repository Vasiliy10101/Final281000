# Настройка приложения для участников канала

## 1. Бот и канал

1. Создать или использовать существующего бота приложения в @BotFather.
2. Сохранить BOT_TOKEN в переменных окружения сервера. Не включать токен в JavaScript, GitHub или channel-config.json.
3. Добавить этого бота администратором нужного канала: это требуется для надёжной проверки других участников методом getChatMember.
4. В channel-config.json заполнить channel_id и channel_url либо задать CHANNEL_ID и CHANNEL_URL на сервере.

Публичный канал: channel_id имеет вид @channel_name. Ссылка будет https://t.me/channel_name. Для закрытого канала указать числовой ID -100… и действующую пригласительную ссылку отдельно.

Без настроенного канала доступ закрыт. Ссылка-приглашение сама по себе не заменяет числовой ID закрытого канала.

Официальное описание проверки: https://core.telegram.org/bots/api#getchatmember

## 2. Размещение

На сервер или в репозиторий для деплоя передать актуальные файлы проекта, включая channel-access.js, channel-config.json и всю папку public. Не включать .env, токены и node_modules.

Команды запуска:

```sh
npm install
npm start
```

Использовать HTTPS. Подключить Postgres и передать DATABASE_URL для сохранения дневника. Сервер создаёт недостающие таблицы и колонки при запуске; стирать существующую базу не требуется.

В настройках бота задать HTTPS-адрес приложения как Menu Button URL. Открывать приложение следует из Telegram, чтобы оно получило подписанные данные входа.

## 3. Переменные

| Переменная | Назначение |
|---|---|
| BOT_TOKEN | Проверка подписи входа и запросы проверки подписки |
| CHANNEL_ID | @username канала или числовой ID -100…; приоритет над channel-config.json |
| CHANNEL_URL | Ссылка кнопки подписки, особенно для закрытого канала |
| DATABASE_URL | Postgres для дневника и профилей |
| ADMIN_IDS | Telegram ID через запятую для административной команды /stats |
| PUBLIC_URL | HTTPS-адрес приложения |
| WEBHOOK_SECRET | Секрет для ручного режима вебхука и его настройки |
| BOT_MODE | polling (по умолчанию), webhook или off; режим обработки команд бота |
| LEGACY_RADAR_ENABLED | Старый радар отключён; 1 включает его отдельно от новой ленты PUMP DUMP |
| LEGACY_EARN_ENABLED | Старые API колеса и заданий отключены; 1 включает совместимость со старой версией |
| PGSSL | require, если база требует SSL |
| PORT | Порт сервера, по умолчанию 3000 |
| PUMP_DUMP_RUN_DIR | Папка текущего источника исследовательских сигналов, если он подключён |

По умолчанию bot.js использует long polling и отвечает только на команды пользователей. Для вебхука явно установить BOT_MODE=webhook; в остальных режимах его установка и обработка заблокированы. BOT_MODE=off отключает обработку команд. Не запускать несколько polling-экземпляров одного бота. У бота остались /start, /help, /myid и /stats (последняя — только для администратора).

## 4. Поведение доступа

- Все прикладные /api/* требуют подписанные Telegram initData и участие в канале, включая сигналы, котировки и дневник.
- /api/tg/webhook и /api/tg/setup используют собственные секреты.
- Владелец, администратор и участник канала проходят проверку. Вышедший или исключённый пользователь не проходит её.
- Завершённое разрешение не кешируется: перед каждым прикладным API-запросом подтверждается текущая подписка через Telegram. Только одновременные запросы одного пользователя объединяются в одну проверку. После выхода следующий запрос отклоняется по ответу Telegram. Уже полученные данные нельзя отозвать с устройства.
- Ошибка Telegram или отсутствие настроек закрывают доступ; автоматического перехода в открытый режим нет.
- Аналитика дневника и PUMP DUMP доступны всем подтверждённым подписчикам одинаково.
- Рыночный радар не отправляет личных сообщений. Старые поля платного статуса в базе не используются и не удаляются.

## 5. Проверка после публикации

1. Подписчик открывает приложение из Telegram и видит все разделы.
2. Неподписчик видит кнопку подписки; после вступления и повторной проверки получает доступ.
3. Прямой запрос к /api/pump-dump без подписанного входа возвращает 401.
4. Подписанный вход неподписчика возвращает 403 для прикладных API.
5. Дневник сохраняет и показывает только сделки текущего пользователя.
6. В PUMP DUMP показывается фактический статус источника: остановленный сбор не выдаётся за работающий.

При открытии public/index.html через file:// доступен локальный предпросмотр без проверки подписки. Это исключение только для файлов на компьютере: HTTP/HTTPS и серверный API по-прежнему проверяют подписку. Папку local-preview с сохранёнными сигналами не публиковать; в архив деплоя она не включается.

## Техническая ревизия 28.10.2026

Передавать всю актуальную сборку, включая новый market-proxy.js. При старте сервер сначала завершает миграции базы и только затем принимает запросы; ошибка миграции останавливает запуск. journal.client_id и уникальный индекс (user_id, client_id) предотвращают дубли при повторном сохранении неизменённого черновика. Старые записи сохраняются, их client_id остаётся NULL. Миграция проверена дважды на временной базе PostgreSQL через PGlite; рабочую базу этой сессии не подключали.

Прокси BingX принимает только три публичных метода котировок. Одинаковые одновременные запросы объединяются; кеш: цена 2 секунды, суточный тикер 15 секунд, контракты 5 минут. Тайм-аут 8 секунд. Сбой биржи возвращается как ошибка 502/504, а не успешный ответ.

Старый radar.js не запускается автоматически. Новая лента /api/pump-dump читает готовый источник, но сама сборщик не запускает. Снимок в data/pump-dump-feed.json содержит 116 сохранённых сигналов остановленного теста. Для новых сигналов требуется отдельно настроенный работающий источник. Локальный путь из data/pump-dump-source.json не переносим на сервер: там нужно задать PUMP_DUMP_RUN_DIR либо обслуживаемый файл источника. Пороги сканера этой ревизией не менялись.

Команда /start получает кнопку открытия Mini App, когда заданы HTTPS PUBLIC_URL и личный чат. Секрет вебхука без BOT_TOKEN теперь случайный. Личные рассылки сигналов не добавлены. Официальные требования кнопки: https://core.telegram.org/bots/api#inlinekeyboardbutton .

Для окончательной приёмки после публикации проверить внутри Telegram: вход подписчика и отказ неподписчику; сохранение сделки и повтор после разрыва связи; приватность двух разных аккаунтов; итог недели и административную награду; кнопку открытия и «Назад». Проверить на телефоне прокрутку, клавиатуру, CSV/буфер обмена и анимации. React и базовые стили всё ещё загружаются с внешних CDN: это зависимость от сети.
