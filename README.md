# Трейдер — Telegram Mini App

Приложение для участников канала: калькуляторы, рыночный скринер, PUMP DUMP и дневник сделок. Академия и ИИндикаторы пока показывают SOON.

Все подписчики получают одинаковые функции. Сервер проверяет подписку через Telegram перед выдачей данных. Сигналы отображаются внутри приложения; рассылки сигналов в личные сообщения нет.

## Запуск

Требуется Node.js 18 или новее. Установить зависимости: `npm install`. Запуск: `npm start`.

Настроить переменные окружения:

- `BOT_TOKEN` — токен бота приложения; хранить только на сервере.
- `CHANNEL_ID` — публичный канал вида `@channel_name` или числовой ID закрытого канала вида `-100…`.
- `CHANNEL_URL` — ссылка для кнопки подписки. Для публичного канала выводится из CHANNEL_ID; для закрытого задать пригласительную ссылку.
- `DATABASE_URL` — Postgres для личных профилей и дневника. Без базы записи не сохраняются.
- `ADMIN_IDS` — ID владельцев через запятую: команда `/stats` и управление званием «Наставник» / наградой за помощь в профиле. Подписка на канал для них также обязательна.
- `PUBLIC_URL` — HTTPS-адрес приложения.
- `PGSSL=require` — если подключение к Postgres требует SSL.
- `PORT` — порт HTTP-сервера, по умолчанию 3000.

Вместо CHANNEL_ID и CHANNEL_URL можно заполнить `channel-config.json`. Переменные окружения имеют приоритет. Бот должен быть администратором проверяемого канала.

Если канал или токен не настроены либо Telegram не подтвердил подписку, данные приложения не выдаются. Завершённое разрешение не кешируется: каждый новый прикладной запрос подтверждает текущую подписку. Одновременные обращения одного пользователя разделяют только выполняющуюся проверку. Видимый интерфейс также перепроверяет подписку раз в минуту, при возвращении в приложение, событии Telegram activated и восстановлении сети.

## Основные файлы

- `server.js` — API, база, статика и запуск сервисов.
- `channel-access.js` — подпись Telegram, срок действия входа и проверка участия в канале.
- `channel-config.json` — канал и ссылка подписки; без токенов.
- `public/member-access.js`, `public/member-access.css` — экран входа и запросы к API с подтверждением личности.
- `public/index.html` — интерфейс React, отдельная сборка не требуется.
- `public/pump-dump.js`, `public/pump-dump.css` — вкладки Pump/Dump и плашка последних сигналов на главной.
- `pump-dump-feed.js` — чтение сохранённых или текущих сигналов через защищённый `/api/pump-dump`.
- `bot.js` — ответы на `/start`, `/help`, `/myid`, `/stats`. Самостоятельных рассылок нет.
- `journal.js` — дневник и разборы сделок, записи привязаны к подтверждённому Telegram ID.
- `profile.js` — личный прогресс, итоги недели, награды и счётчики сообщества.
- `public/profile-model.js` — единые условия званий и достижений.
- `public/community-profile.js`, `public/community-profile.css` — карточка входа на главной и полный экран профиля.

Старые поля статуса в существующей базе не удаляются и не используются для доступа. При обновлении не нужно стирать таблицы, сделки или исследовательский архив.

## PUMP DUMP

Главная и вкладки используют один источник и обновляются каждые 10 секунд. Источник задаётся через PUMP_DUMP_RUN_DIR или `data/pump-dump-source.json`; при отсутствии текущего источника используется `data/pump-dump-feed.json`. Сборщик исследовательской системы запускается отдельно. Открытие приложения его не запускает.

Сигналы не встроены в публичный JavaScript: получить их можно только после проверки подписки. Файл `public/pump-dump-data.js` оставлен пустой совместимой заглушкой.

## Проверка

Опубликованное приложение открывается через Telegram: обычный браузер не подтверждает личность. Файл `public/index.html`, открытый через `file://`, работает как локальный предпросмотр без проверки подписки. Он не даёт доступа к защищённому серверному API. Подписчик получает приложение; неподписчик — экран подписки и кнопку повторной проверки. Личный дневник дополнительно ограничен собственным ID пользователя.

Подробности настройки: `DEPLOY.md`. Проверки кода выполняются с подставными ответами Telegram; для сквозной проверки нужны настоящий канал, бот с правами администратора и опубликованный HTTPS-адрес.

Автоматические проверки доступа и интерфейса: `npm test`. Они используют тестовые ответы вместо обращений к Telegram.

## Локальный предпросмотр

При открытии public/index.html с диска интерфейс доступен без Telegram и помечен как «Локальный просмотр». Сохранённые сигналы для него загружаются из local-preview/pump-dump-data.js вне public/. Эта папка исключена из Git и архива публикации. Если локального архива нет, интерфейс всё равно открывается с пустой лентой. На HTTP/HTTPS, в том числе localhost, проверка подписки обязательна.

## Профиль и сообщество

На главной вся карточка с аватаром, именем и подписью «Мой профиль» открывает отдельный экран. В нём есть сообщество, следующее звание, достижения, итоги недели и закрытая по умолчанию личная статистика. Сведения о сделках и тексты разборов доступны только их автору. Публичного рейтинга доходности нет.

Условия званий:

| Звание | Условие |
| --- | --- |
| Участник | Первый вход в приложение |
| Исследователь | Полные разборы сделок в 5 разных днях |
| Практик | 5 дней с разборами и итоги 4 разных недель |
| Стратег | 5 дней с разборами, итоги 8 разных недель и итоговый разбор |
| Наставник | Назначение владельцем за помощь сообществу |

Разбор засчитывается, если в записи сделки заполнены «Причина входа» и «Вывод по сделке»: от 20 до 1000 символов после удаления пробелов по краям в каждом поле. Это проверка заполнения, а не автоматическая оценка качества текста. Несколько разборов в один день дают один шаг. Старые записи без этих полей не засчитываются автоматически. При удалении записей прогресс пересчитывается и может уменьшиться. Прибыль, торговый объём, частота сделок и старые баллы не повышают звание.

Итоги недели: от 40 до 2000 символов. Неделя начинается в понедельник по Москве. Запись относится к текущей неделе по времени сервера; повторное сохранение обновляет её, не увеличивая счётчик. Итоговый разбор доступен после 8 разных недель. В профиле показываются и редактируются итоги текущей недели; предыдущие хранятся в базе.

Число участников канала запрашивается через [Telegram getChatMemberCount](https://core.telegram.org/bots/api#getchatmembercount), успешный результат сохраняется на 5 минут. При ошибке остаётся последнее значение с пометкой, при отсутствии данных — прочерк. «Активны за 7 дней» — число пользователей с подтверждённой активностью в приложении за этот срок, а не онлайн в Telegram. Учёт начинается после установки этой версии. Дата «В приложении с…» — первый зафиксированный вход в приложение, не дата подписки на канал.

Профиль обновляется раз в минуту на видимой странице, при возвращении в приложение и после изменений дневника. Локальный просмотр с диска показывает интерфейс с начальным званием и недоступными счётчиками; сохранение и назначение наград требуют сервера, Telegram и Postgres.

Владелец из ADMIN_IDS видит блок «Управление званиями». Участник получает свой ID командой /myid у бота и передаёт владельцу. Владелец может присвоить или снять «Наставника» и достижение «Вклад в сообщество». Сервер проверяет права независимо от отображения этого блока.

## Калькулятор, скринер и дневник — обновление 28.10.2026

Единый калькулятор без режимов «Простой / Профи» и ползунка. План: монета, направление, депозит, риск, вход, стоп, необязательная цель, плечо и комиссия. Объём по риску учитывает комиссию открытия и закрытия на стопе. При своём количестве монет показывается фактический риск и превышение бюджета. Нехватка средств проверяется по начальной марже плюс комиссии входа. Приведение количества к шагу конкретного контракта не выполняется.

Дополнительные раскрывающиеся блоки: свой объём, безубыток, приблизительная ликвидация для изолированной маржи, частичные выходы и фандинг. Приближение ликвидации: entry × (1 − direction / leverage) / (1 − direction × maintenanceRate), без комиссий, дополнительных средств и ступеней риска. Это не биржевой расчёт ликвидации. Фандинг оценивается при постоянных цене входа и ставке, с учётом стороны; фактическая база биржи — mark price на время выплаты. Фандинг и проскальзывание не входят в показанные результаты сделки. Стартовая комиссия 0,05% явно обозначена как пример.

Базовые формулы сверены с [расчётом P&L](https://www.bybit.com/en/help-center/article/Profit-Loss-calculations-USDT-Contract) и [расчётом фандинга Bybit](https://www.bybit.com/en/help-center/article/Funding-fee-calculation). Пользователь вводит свою комиссию; автоматического получения тарифов и лимитов биржи нет.

Скринер: поиск, избранное, рост/падение, сортировка по объёму и силе движения, минимальный объём, диапазон цены за 24 часа и переход в калькулятор. Показаны именно изменения за сутки, не сигналы PUMP DUMP за 1–5 минут. Котировки обновляются каждые 30 секунд, пока открыт главный экран или скринер и документ видим. При сбое сохраняются последние котировки с отметкой об ошибке. Примеры доступны только в локальном file-просмотре и явно подписаны; примерные или устаревшие цены не переносятся как текущие в калькулятор.

Дневник: черновик, предварительный P&L без комиссий, необязательный разбор с эмоциями, поиск по монете, периоды 7/30 дней и всё время, фильтры результатов и неполных разборов. Список, статистика и CSV относятся к одному отфильтрованному набору. Дата записи — серверное время добавления, не историческая дата закрытия сделки. Загружаются последние 500 записей; наличие более старых записей явно отмечается. Удаление требует отдельного подтверждения. После ошибки сохранения черновик сохраняется; его идентификатор предотвращает дубль при повторной отправке без изменения полей. После неопределённого результата запроса также предложено обновить историю. CSV включает заметку и оба поля разбора, экранирует кавычки/переносы и текстовые формулы.

Избранное, настройки и черновики сохраняются на устройстве и синхронизируются через PostgreSQL после подтверждения аккаунта. Локальный file-просмотр использует отдельную память preview и не синхронизируется с Telegram. Для личных серверных записей продолжают действовать проверка подписки и привязка к подписанному Telegram ID. В file-просмотре можно заполнить черновик, но личная история и сохранение на сервер недоступны.

Переходы: скринер → калькулятор → черновик дневника. Перед заменой существующих полей пользователь применяет переданные параметры. Из калькулятора никогда не переносится цена выхода или готовый результат — запись сохраняется только после заполнения фактического выхода.

Новые файлы: public/trading-model.js, public/trading-tools.js и public/trading-tools.css. Проверки математики, фильтров, ошибок, черновиков и действий: tests/trading-tools.test.js. В технической ревизии сервер проверен изолированно с временной базой и подставным Telegram; рабочий бот и сборщики не запускались.

## Оформление Onest

Единый стиль «Спокойный»: public/onest-theme.css, шрифт Onest, облегчённые заголовки и плоские карточки. Начертания заголовков преимущественно 500, обычный текст 400. Нижнее меню выделяет активный раздел цветом. Блок «Рынок · 24 ч» на главной раскрывается по нажатию.

Шрифт встроен в CSS, поэтому доступен и при локальном открытии без отдельного запроса к Google Fonts. Лицензия: public/fonts/OFL-Onest.txt. Источник: https://github.com/google/fonts/tree/main/ofl/onest. При обновлении передавать этот CSS и файл лицензии вместе с остальной папкой public.

## Анимации интерфейса

public/app-motion.css задаёт общие длительности и плавность: 140–180 мс для кнопок и полей, 220–260 мс для появления блоков и переходов. Основные разделы остаются смонтированными, поэтому переключение сохраняет введённые значения и фильтры. Новые сигналы и уведомления появляются мягко; обновление значений в существующей карточке не перезапускает анимацию.

public/app-motion.js плавно раскрывает графики, формы и дополнительные достижения, а также стандартные details. Повторное действие отменяет предыдущую анимацию; закрывающийся контент сразу исключается из взаимодействия. Анимации не откладывают запросы или сохранение. Индикаторы загрузки связаны с реальным состоянием запроса.

При prefers-reduced-motion движения и вращение отключаются, включая уже начатое раскрытие. Если Web Animations API недоступен, блоки открываются и закрываются сразу. Новых библиотек, фоновых сервисов и запросов к внешним сервисам слой анимаций не добавляет.

Это проверка поведения компонентов и запросов, не визуальный тест браузера. Публичный запрос цены BingX отдельно вернул HTTP 200 и положительную цену.

Исправлено: дубли сделок при повторе; строгая проверка серверных чисел и ID; потеря черновиков профиля при переключении и перезагрузке; перенос старого итога в новую неделю; зависание сохранения при отсутствии ответа; смешивание растущих монет с падающими на главной; синхронизация адреса раздела и кнопка «Назад» Telegram; некорректные записи и даты в ленте сигналов; запуск сервера до завершения миграций; отсутствие ограничений времени и объединения запросов котировок. Неиспользуемые старые функции отключены по умолчанию.

Черновики итогов недели и итогового разбора сохраняются на устройстве отдельно по участнику; обновление памяти ниже добавляет синхронизацию через сервер. Сохраняются до 20 черновиков; несохранённые прошлые недели доступны для чтения в профиле. Сервер отклоняет попытку сохранить итог от другой недели, сохраняя текст на устройстве.

Проверки npm test входят в проект. Дополнительные сценарии Express/PostgreSQL и React, журналы результатов и точные версии тестовых зависимостей сохранены в рабочей папке work/technical-audit/test-runtime; они не увеличивают зависимости приложения. Настоящие Telegram, рабочая PostgreSQL, мобильный браузер, нагрузка 200 пользователей и работа сканера в реальном времени этой проверкой не подтверждены. Академия, ИИндикаторы и AI-трейдер остаются предусмотренными заглушками SOON.


## Память участника — 28.10.2026

Единственная серверная идентичность — Telegram ID из подписанных initData после проверки участия в канале. /api/access возвращает подтверждённый userId; память интерфейса создаётся только после этой проверки. Имя и username обновляют тот же аккаунт. ID из тела и строки запроса не выбирают владельца данных. Владелец не получает через API доступ к чужим сделкам или черновикам.

Таблица user_state хранит восемь видов данных по (user_id, state_key): calculator, calculator-exits, favorites, screen-filters, journal-draft, journal-filters, profile-drafts, pump-direction. Схема и ограничения общие у клиента и сервера: public/user-state-model.js. Звания, дневник, сохранённые итоги и награды продолжают храниться в своих таблицах. Выход из канала не удаляет данные.

GET /api/user-state возвращает только данные подписанного участника. PUT принимает key, value, baseRevision, operationId. Обновление сравнивает ревизию атомарно в базе. Конфликт возвращает 409 и текущую версию; интерфейс сохраняет обе версии до выбора. Повтор потерянного ответа безопасен. Настройки обновляются целиком по своему виду, а не объединяются по отдельным полям. Черновик не становится закрытой сделкой и не даёт достижения до явного сохранения.

Клиент сохраняет изменения локально сразу и отправляет через 700 мс после последнего изменения. При видимой странице сверяет сервер раз в 30 секунд, при восстановлении сети и возвращении в приложение. Если возник конфликт, его нужно разрешить вверху экрана. Форма сделки и итоги блокируют окончательное сохранение конфликтующего черновика до выбора. История дневника также обновляется при возвращении на видимую страницу и восстановлении связи.

При временной ошибке сети уже подтверждённая открытая сессия позволяет продолжать черновик; серверные проверки не отключаются. Явные auth/not_member закрывают интерфейс. После полного закрытия и нового запуска нужен интернет для подтверждения входа. Это не полноценный автономный запуск: код приложения зависит от сети/CDN. Удаление данных браузера до синхронизации удалит локальные несинхронизированные черновики. Локальный просмотр имеет отдельную память и не переносится автоматически в чей-либо Telegram.

В профиле владельца: число пользователей приложения, активность за 7/30 дней, количества званий и полученных достижений. GET /api/community/summary доступен только ADMIN_IDS и возвращает агрегаты без чужих текстов, P&L и идентификаторов. Число участников канала по-прежнему запрашивается отдельно через Telegram.

## Комплексная проверка — текущая ревизия 28.10.2026

106 проверок прошли: 76 основных, 10 PUMP DUMP, 11 HTTP/PGlite и 9 React. Отчёт REVIEW-2026-10-28.html описывает исправления и ограничения; числа в предыдущих разделах относятся к прошлым ревизиям.

Несколько окон: При сохранении локальной памяти одно окно могло затереть несинхронизированные поля другого. Добавлены сверка записей и обработка изменений общего хранилища. Разные поля сохраняются вместе; при конкурирующем изменении одного поля показываются две версии.

Обрыв связи после сохранения: Если сервер успел принять запись, а ответ потерялся, следующая правка ошибочно конфликтовала с собственным сохранением. Клиент сохраняет сведения об отправленной операции, сервер возвращает её идентификатор; восстановление проверено и после перезагрузки.

Сохранённые разборы профиля: Два устройства могли молча перезаписать один итог недели или итоговый разбор. Сервер теперь атомарно сравнивает исходный текст. При конфликте интерфейс показывает обе версии и требует выбора. Автоматическое обновление профиля не меняет исходную версию редактируемого черновика.

Черновик во время отправки: Позднее подтверждение сделки или разбора могло заменить более свежий черновик. Подтверждение теперь очищает или помечает только отправленную версию. Новые изменения сохраняются.

Смена недели: Запрос, начатый перед полуночью понедельника по Москве и завершённый после неё, мог сохранить текст под другой неделей. Используется одна дата недели, проверенная при начале запроса.

Старые черновики дневника: Черновик без корректного идентификатора отправки мог не сохраняться, пока пользователь не изменит поле. Идентификатор восстанавливается автоматически с сохранением всех полей.

Граничные значения калькулятора: Добавлена защита от численного переполнения в оценке фандинга и частичных выходах; слишком большие значения не становятся корректным результатом.

Учёт приглашений: Привязка приглашённого и начисление выполнялись отдельными запросами. Теперь это одна атомарная операция: ошибка откатывает оба изменения, повтор не начисляет дважды. Слишком большие и некорректные ID отклоняются.

GET/PUT user-state теперь возвращает operationId последней принятой операции. При потере ответа клиент сопоставляет его с сохранённой отправкой. Общий локальный кеш сверяется перед записью и при событии storage; конкурирующие версии требуют выбора.

POST /api/profile/reflection требует baseBody (исходный сохранённый текст, пустая строка при первом сохранении), kind, body и week для недельного разбора. Несовпадение возвращает 409 reflection_conflict с текущим body только владельцу. Приложение сохраняет baseBody вместе с черновиком и предлагает выбрать версию. Повтор той же сохранённой версии безопасен. Старый клиент без baseBody получает reflection_version_required.

Доступность настоящего Telegram, рабочей PostgreSQL, мобильная вёрстка и нагрузка остаются непроверенными. Сервер, бот и сборщик не запускались в рабочем режиме.
